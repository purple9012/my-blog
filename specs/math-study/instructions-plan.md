# Plan 서브에이전트 지침 — AI를 위한 수학 공부 웹

## 목표
`specs/math-study/spec.md`를 작성한다. 사용자는 **기술 스펙 중심으로만 확인**하고 나머지는 빠르게 진행하길 원한다. 따라서 spec.md 맨 위에 "기술 스펙 요약"(스택, 라이브러리와 버전, 파일 구조, 데이터 형식)을 한 화면 분량으로 두고, 그 아래에 상세 내용을 둔다.

## 수정 가능 범위
- 생성/수정: `specs/math-study/spec.md` **단 하나**
- 그 외 모든 파일은 읽기만. 구현 금지.

## 사용자 요구사항
- 대상: 사용자 본인의 개인 학습용
- 주제: **AI를 위한 수학** — 고등수학부터 쉽게 시작해서 AI에 필요한 수학(선형대수, 미적분, 확률·통계)으로 이어지는 흐름
- 기능: 개념 정리, 문제 풀이와 퀴즈(정답/해설), 진도 체크
- 위치: 기존 `my-blog` 사이트(`index.html`)의 새 메뉴
- 최대한 빠르게 구현할 수 있도록 **범위를 작게**: 초기 콘텐츠는 3~4개 단원이면 충분하고, 나중에 단원을 쉽게 추가할 수 있는 구조여야 한다.

## 제약
- GitHub Pages 정적 호스팅: 서버 코드, 빌드 단계 없음. 상대경로만 사용(`/assets/...` 절대경로 금지, 파일명 대소문자 일치).
- 수식 렌더링은 KaTeX를 쓰되 CDN 사용 시 **정확한 버전 고정**(cdnjs.cloudflare.com 또는 cdn.jsdelivr.net/npm 등), 가능하면 오프라인 대비책도 한 줄로 언급.
- 진도·퀴즈 기록은 `localStorage`(키 이름 명시, 파싱 실패 시 빈 상태로 시작).
- 기존 `assets/css/style.css`(딥그린 다크 테마 변수) 재사용.
- 현재 `index.html`은 헤더에 제목, 본문에 `todo.html` 링크만 있는 상태다. 읽고 새 링크 추가 위치를 정확히 명시.
- 수학 콘텐츠는 틀리면 안 된다. 초기 단원 목록과 각 단원에서 다룰 개념을 spec에 구체적으로 적고, 콘텐츠 작성 시 검증 방법(계산 확인)을 명시.

## spec.md 구성
1. 기술 스펙 요약 (맨 위, 표 형태): 스택 / KaTeX 버전 / 파일 구조 / 콘텐츠 데이터 형식(JS 파일 vs JSON 등 — `file://`과 Pages 모두에서 동작해야 함을 고려) / localStorage 키
2. 개요와 범위(제외 항목 포함)
3. 학습 로드맵과 초기 단원 목록 (3~4개, AI 연결 포인트 한 줄씩)
4. 화면 구성: 화면 수와 각 화면의 역할(예: 단원 목록 / 단원 학습 / 퀴즈), 와이어프레임 텍스트
5. 단원 콘텐츠 데이터 스키마와 새 단원 추가 방법
6. 구현 분담안: 화면이 3개 이상이면 화면별 서브에이전트 분담과 **겹치지 않는 파일 범위**, 공통 파일 담당 정리
7. index.html 변경 내용
8. 검증 체크리스트 (Review용): 수식 렌더링, 퀴즈 채점, 진도 저장/복원, 깨진 localStorage, 모바일 폭, 링크 이동, 수학 내용 정확성
9. 열린 질문 (최소한으로, 기본값 포함)

## 규칙
- 한국어로 간결하게 작성.
