# Review: 2048 게임

테스트 환경: `python -m http.server`로 로컬 정적 서버(`http://localhost:8642`)를 띄운 뒤 Browser 도구로 `game-2048.html`을 열어 확인. 데스크톱(1280x800) / 모바일(375x812) 두 뷰포트에서 확인.

## 테스트 결과

- **방향키 4방향 이동/병합, 점수 갱신**: PASS. `dispatchEvent(KeyboardEvent('keydown', {key:'ArrowUp'}))` 및 실제 게임 로직을 통해 확인. 예: 두 개의 `2` 타일을 위로 밀어 `4`로 병합, `SCORE`/`BEST`가 즉시 `4`로 갱신됨. 이후 자동 플레이 스크립트로 수만 회 이동을 실행해 여러 판을 진행, 로직이 안정적으로 동작함을 확인(최대 `1024` 타일까지 여러 차례 도달, 점수 16000대까지 확인). 콘솔 에러 없음.
  - 참고: Browser 도구의 `computer{action:"key"}` 실제 키 입력이 이 세션에서 간헐적으로 유실되는 현상이 있었음(첫 `Right`는 반영, 이후 `Down`/`Left`가 반영 안 됨). `document.dispatchEvent(new KeyboardEvent(...))`로 전환해 안정적으로 재현·검증함. 이는 브라우저 자동화 도구 자체의 이슈로 보이며, 실제 사용자의 물리 키보드 입력과 동일한 `keydown` 이벤트로 검증했으므로 게임 코드 자체의 문제는 아님.
- **"새 게임" 버튼 (점수 리셋, 최고점수 유지)**: PASS. 클릭 시 `score`가 `0`으로, 타일이 2개로 초기화되고 `best`는 이전 최고점수를 유지함(예: `best=4` 유지).
- **최고 점수 localStorage 저장/유지**: PASS. `localStorage.getItem('game2048BestScore')`에 값이 저장되고, `game-2048.html`을 새로고침(재 `navigate`)해도 `data-best`에 동일 값이 표시됨.
- **모바일 뷰포트 레이아웃**: PASS. 375px 폭에서 `.game-2048-board-wrap`이 335px로 뷰포트 안에 들어오고(`min(420px, calc(100vw - 2.5rem))` 적용 확인), `document.documentElement.scrollWidth > window.innerWidth`가 `false`로 가로 스크롤 없음.
- **스와이프 동작**: PASS. `Touch`/`TouchEvent`로 `touchstart`→`touchend`(좌측으로 100px 이동) 시퀀스를 보드 요소에 디스패치한 결과, 보드가 왼쪽으로 밀리고 새 타일이 생성됨을 확인(방향 판정 정상).
- **게임 오버 재현**: PASS(실제 재현). 자동 플레이 스크립트로 여러 판을 실제로 끝까지 진행시켜 게임 오버를 다회 재현함. 오버레이 메시지 "게임 오버! 최종 점수 {score}"가 정확히 표시되고, `data-overlay-retry` 버튼 텍스트가 "다시 시작"으로, 승리용 "계속하기" 버튼(`data-overlay-continue`)은 DOM에 없음을 확인. "다시 시작" 클릭 시 오버레이가 닫히고 점수 0/타일 2개로 정상 리셋, `best`는 유지됨.
- **2048 승리 오버레이의 "계속하기"/"새 게임" 두 버튼**: PARTIAL — 코드 리뷰 + 간접 검증으로 대체, 완전한 실기 재현은 실패. 아래 "발견된 문제"에 상세 기술.
- **index.html → game-2048.html → "← 목록으로" 내비게이션**: PASS. `index.html`의 "2048 게임" 링크 클릭 시 `game-2048.html`로 정상 이동. `game-2048.html` 상단 "← 목록으로" 링크(`href="index.html"`)도 확인.
- **콘솔 에러 유무**: PASS. 세션 전체(수십만 회의 이동 디스패치 포함)에서 콘솔 에러/경고 없음.

## 발견된 문제

- **[심각도: medium] 2048 승리 오버레이의 "계속하기"/"새 게임" 두 버튼 동작을 실제 2048 타일 생성으로 완전히 재현하지 못함.**
  - 재현 시도: `game-2048.js`가 IIFE로 `board` 등 상태를 완전히 캡슐화하고 있어(전역/디버그 훅 없음), devtools 콘솔에서 지침이 제안한 "board 상태를 강제로 조작"하는 방법이 불가능했다(코드 수정 없이는 board를 직접 세팅할 방법이 없음 — 오히려 캡슐화 자체는 잘 되어 있다는 뜻이므로 이 자체는 버그 아님). 대신 실제 `keydown` 이벤트를 반복 디스패치하는 자동 플레이(그리디/스네이크 가중치 휴리스틱, 총 수십만 회 이동, 약 1500+ 판 진행)로 실제 2048 타일 도달을 시도했으나, 주어진 시간 내에는 최대 `1024` 타일까지만 반복 도달했고 `2048` 타일 생성(및 그에 따른 승리 오버레이 노출)은 실기로 확인하지 못했다.
  - 대신 확인한 것: (1) 병합 로직이 `2→4→8→...→1024`까지 코드 경로 변경 없이 동일하게 동작함을 실측으로 확인했고, `slideRowLeft`/`moveBoard`에 타일 값에 따른 분기가 전혀 없으므로 `1024→2048` 병합도 동일하게 동작할 것으로 강하게 추정된다. (2) `showWinOverlay`/`showGameOverOverlay`/`ensureContinueButton`/`onContinueClick`/`onRetryClick`의 소스코드를 정독한 결과: 승리 시 `overlayRetryBtn` 텍스트를 "새 게임"으로 바꾸고 그 클릭 핸들러는 그대로 `onRetryClick`(→`newGame()`)이므로 "새 게임" 버튼은 의도대로 동작할 것으로 보인다. "계속하기" 버튼은 `insertBefore`로 `overlayRetryBtn` 앞에 삽입되고 클릭 시 `hideOverlay()`만 호출해 오버레이를 닫고 게임 상태(`board`, `score`, `hasWon`)는 그대로 유지하므로 스펙 3.5/4.6 요구사항과 부합해 보인다. 게임 오버 경로에서 `showGameOverOverlay()`가 `overlayContinueBtn`을 DOM에서 제거하고 재게임 시(`newGame()`)에도 동일하게 제거하는 정리 로직이 있음을 실기로 간접 확인했다(승리 후 이어하다 게임 오버가 나면 "계속하기" 버튼이 사라지고 "다시 시작"으로 복귀하는 코드 경로가 게임 오버 테스트에서 실제로 발동됨).
  - 결론: 코드상 로직은 스펙과 일치하고 버그 징후는 발견되지 않았으나, **실제로 승리 오버레이가 뜬 상태에서 "계속하기"/"새 게임" 두 버튼을 클릭해보는 최종 확인은 이번 리뷰에서 완료하지 못했다.** 커밋 전 또는 커밋 후라도, 실제 브라우저에서 짧게라도(예: 임시로 `boardHasValue`의 타깃을 낮춰 로컬에서만 확인 후 되돌리는 등) 승리 오버레이의 두 버튼을 최소 한 번은 사람이 직접 눌러 확인할 것을 권장한다.

- **[심각도: low] Browser 자동화 도구의 실제 키보드 입력(`computer{action:"key"}`)이 이 리뷰 세션에서 간헐적으로 씹힘.**
  - 재현: 페이지 로드 직후 `Right` 키는 정상 반영됐으나 곧이어 누른 `Down`, `Left`는 반영되지 않음(여러 차례 재현). `document.dispatchEvent(new KeyboardEvent('keydown', {key:...}))`로 동일 이벤트를 보내면 항상 정상 동작.
  - 관련 파일: 없음(게임 코드가 아니라 이번 리뷰에 사용한 브라우저 자동화 도구 자체의 특성으로 판단됨). 실제 사용자의 물리 키보드는 동일한 `keydown` 네이티브 이벤트를 발생시키므로 게임 사용에는 영향이 없을 것으로 판단한다. 참고 목적으로만 기록.

## 결론

- 핵심 기능(4방향 이동/병합/점수, 새 게임, 최고점수 저장, 모바일 레이아웃/스와이프, 게임 오버, 내비게이션, 콘솔 에러 없음)은 모두 실기 검증을 통과했다.
- **추가 확인 (2026-08-08)**: 위에서 medium으로 남겨졌던 승리 오버레이 "계속하기"/"새 게임" 두 버튼을, `game-2048.js`의 승리 조건을 `2048`→`8`로 임시 변경해 실제로 승리 상태를 재현한 뒤 두 버튼을 각각 클릭해 검증했다.
  - "계속하기": 오버레이만 닫히고 점수/보드 상태가 그대로 유지됨을 확인 (score 20 → 20 유지).
  - "새 게임"(승리 시 텍스트가 바뀐 `data-overlay-retry`): 클릭 시 점수 0으로 리셋, 최고점수는 유지됨을 확인.
  - 이후 게임을 계속 진행해 게임 오버 상태로도 전이시켜, `overlayContinueBtn`이 DOM에서 정상적으로 제거되고 "다시 시작" 텍스트로 복귀하는 것도 함께 확인.
  - 검증 후 승리 조건을 `2048`로 즉시 원복, 재로드하여 콘솔 에러 없음과 정상 동작을 재확인함.
  - 이로써 medium 이슈는 **해소**됨.
- **커밋 가능** — blocking(high) 이슈 없음, 남아있던 medium 이슈도 실기 검증으로 해소됨. (low 이슈였던 Browser 자동화 도구의 키 입력 유실은 게임 코드와 무관하여 별도 조치 불필요.)
