# 지침: 2048 게임 spec 작성

## 배경

`my-blog`는 마크다운 기반 정적 블로그 프로젝트다 (프레임워크 없이 순수 HTML/CSS/JS만 사용, CLAUDE.md 참고). 이번 작업은 블로그에 2048 게임 페이지를 추가하는 것이다.

## 요구사항 (사용자 요청 원문)

- 2048 게임: 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임
- 점수판 포함

## 당신의 임무

`specs/2048-game/spec.md` 파일 하나만 작성한다. 코드는 작성하지 않는다. 이 저장소의 기존 구조(`index.html`, `assets/css/style.css`, `assets/js/*.js`)를 읽어서 기존 디자인 시스템(색상 변수, 다크모드 처리 방식, 레이아웃 컨벤션)과 일관되게 통합할 방법을 파악한 뒤 spec에 반영한다.

spec.md에는 다음 내용을 포함할 것:

1. **개요**: 기능 요약
2. **파일 구조**: 새로 만들 파일 목록과 경로 (예: `game-2048.html`, `assets/js/game-2048.js`, 필요시 전용 CSS 파일 또는 style.css에 추가할 섹션)
3. **화면/UI 명세**:
   - 4x4 그리드 보드
   - 타일 색상/스타일 (숫자별 구분, 다크모드 대응)
   - 점수판 (현재 점수, 최고 점수 - localStorage 저장)
   - 새 게임 버튼
   - 게임 오버 / 승리(2048 타일 생성 시) 표시
4. **게임 로직 명세**:
   - 방향키(↑↓←→) 입력 처리, 타일 이동/병합 규칙
   - 모바일 대응: 스와이프 제스처 지원 여부 (반응형 원칙상 필요)
   - 랜덤 타일 생성 규칙 (2 또는 4, 확률)
   - 게임 오버 판정 로직
5. **네비게이션**: 기존 index.html/nav에서 게임 페이지로 연결하는 방법 (헤더 메뉴 등)
6. **작업 분할 제안**: Work 단계에서 몇 개의 서브에이전트로 나눌지, 각각의 범위를 명확히 겹치지 않게 제안 (예: "UI/마크업+CSS 담당" / "게임 로직 JS 담당" 등). 화면 자체는 1개(게임 페이지 1개)뿐이므로 화면 단위 분할보다는 관심사(레이아웃/스타일 vs 로직) 단위로 나누는 방안을 제시할 것.

## 제약

- 이 저장소는 "노 프레임워크" 원칙이다 (React, Vue, 번들러, npm 빌드툴체인 금지). spec도 이 제약을 지켜야 한다.
- `specs/2048-game/spec.md` 외의 다른 파일은 만들거나 수정하지 않는다.
