# 지침: 2048 게임 Review

## 배경

`specs/2048-game/spec.md`에 따라 2048 게임 페이지가 구현되었다 (`game-2048.html`, `assets/css/game-2048.css`, `assets/js/game-2048.js`, `index.html`/`style.css` 네비 링크 추가).

구현 중 알려진 이슈 하나: 게임 로직 담당자가 "승리 시 계속하기/새 게임 두 버튼" 요구사항(spec 3.5, 4.6)을 구현할 때, HTML에는 `data-overlay-retry` 버튼 하나만 있어서 JS가 런타임에 "계속하기" 버튼을 동적으로 `insertBefore`로 생성하고 `data-overlay-retry`의 텍스트를 상황에 따라 바꾸는 방식으로 우회했다. 이 부분이 실제로 잘 동작하는지 특히 주의 깊게 확인하라.

## 범위

- `specs/2048-game/review.md` 파일을 작성한다. 그 외 다른 파일은 수정하지 않는다 (버그를 발견해도 직접 고치지 말고 review.md에 기록만 한다).

## 해야 할 일

1. `specs/2048-game/spec.md`를 읽어 요구사항을 파악한다.
2. `game-2048.html`, `assets/css/game-2048.css`, `assets/js/game-2048.js`, `index.html`, `assets/css/style.css`의 변경사항을 읽는다.
3. Browser 도구로 로컬 정적 서버를 띄우고(`file://`는 스크립트/CSS가 막힐 수 있으니 가능하면 정적 서버 사용) `game-2048.html`을 연다.
4. 다음을 실제로 조작해 테스트한다:
   - 방향키 4방향 이동/병합, 점수 갱신
   - "새 게임" 버튼 (점수 리셋, 최고점수 유지)
   - 최고 점수 localStorage 저장/유지 (새로고침 후에도 유지되는지)
   - 모바일 뷰포트로 리사이즈 후 레이아웃 확인, 스와이프 동작 여부(가능한 범위에서)
   - 게임 오버 상황 재현 시도 (시간이 오래 걸리면 devtools/console에서 board 상태를 직접 조작하거나 코드 리뷰로 대체 가능하되, 가능하면 실제 재현 우선)
   - **2048 타일 도달 시 승리 오버레이의 "계속하기"/"새 게임" 두 버튼이 정상 노출되고 각각 의도대로 동작하는지** — 시간이 오래 걸리면 콘솔에서 `board` 상태를 강제로 조작해 2048 타일을 만들어서라도 반드시 실제 확인한다.
   - index.html 헤더의 "2048 게임" 링크로 진입, game-2048.html 상단 "← 목록으로" 링크로 복귀
   - 콘솔 에러 유무
5. 발견한 문제를 심각도와 함께 정리한다.

## review.md 형식

```
# Review: 2048 게임

## 테스트 결과
- (항목별 pass/fail, 확인 방법)

## 발견된 문제
- [심각도: high/medium/low] 설명, 재현 방법, 관련 파일

## 결론
- 커밋 가능 여부 (blocking 이슈 없으면 "커밋 가능", 있으면 무엇을 고쳐야 하는지)
```
